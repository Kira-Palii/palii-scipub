# Правила роботи з репозиторієм

## Гілки
Кожна задача має власну гілку від актуального `main`. Префікси:
- `feature/` нова функціональність (`feature/title-normalizer`)
- `fix/` виправлення помилки
- `refactor/` зміна структури без зміни поведінки
- `docs/` документація
- `chore/` службові зміни та конфігурація

## Коміти
Формат повідомлення: `тип: короткий опис` (до 60 символів, наказовий спосіб),
наприклад `feat: add title normalizer`. Один коміт містить одну логічну зміну.

## Pull request
- до 300 змінених рядків;
- опис за шаблоном: що зроблено, навіщо, як перевірити;
- перед запитом проходять `ruff check` і `ruff format`;
- у діфі немає `.venv`, `.env`, баз даних і кешів;
- злиття у `main` лише через pull request після рев'ю.
